# 1.2 — Module 1 (DPREQ): Workflow and Status States

> **2026-07-02:** Per `0.4-dpo-ethics-integration.md`, this is the **DPO track only** — one of
> two parallel tracks acting on the same Form 1 submission (the other being REMIS/Ethics, `3.3`).
> This module's `Approved` status is necessary but not sufficient for clearance issuance: the
> **Clearance Issued** step below now requires the Ethics track (`3.3`) to have also reached a
> positive decision. See `CHANGELOG.md`.

## Status Lifecycle

> **⚠️ UPDATED 2026-07-25 — collapsed to Review → Approve.** The old four-action chain
> (`Screening → Under Review → Endorsed → Approved`), all performed by the single DPO Staff role,
> was redundant. `Screening` and `Endorsed` are retired; the flow is now two staff actions: take an
> application **Under Review**, then **Approve** / **Return** / **Reject**. Also note the DPREQ
> clearance now issues **independently** of the Ethics track (2026-07-25) — it is no longer withheld
> for a second signature.

```
Draft → Submitted → Under Review → Approved → Clearance Issued
                         |
                         v
                     Returned  ──→ Submitted   (and Under Review → Rejected)
```

| Status | Description | Actor who moves it |
|---|---|---|
| Draft | Applicant is filling out form, not yet submitted | Applicant |
| Submitted | Application sent to DPO | Applicant |
| Under Review | DPO Staff reviews completeness + data-privacy requirements | DPO Staff |
| Returned | Incomplete/incorrect — sent back to applicant with comments | DPO Staff |
| Rejected | Application denied, with reason | DPO Staff |
| Approved | DPO Staff signs off (DPO Approver retired 2026-07-06; DPO Staff owns the track end to end) | DPO Staff |
| Clearance Issued | Data Privacy Clearance generated + released **independently** of the Ethics track (2026-07-25) — see `0.4-dpo-ethics-integration.md` | System (auto, on DPO approval) |

## Review Procedure (2026-07-25)
1. DPO Staff takes the application **Under Review** (`startReview`) and completes the screening
   checklist.
2. If more is needed, DPO Staff can either **Return for Correction** (→ Returned, mandatory comments)
   or **request additional requirements** (a mandatory revision request — item 7 · FRS §IX — which
   blocks approval until the applicant supplies it).
3. DPO Staff then **Approves** (triggers clearance generation + e-signature; blocked until the
   Research Team NDA is signed and no required revision item is outstanding) or **Rejects** (with
   mandatory reason).

## Screening Checklist (confirmed with DPO 2026-07-06 — the actual SOP, no longer a sample)
- [ ] Research proposal attached and legible
- [ ] Data privacy impact assessment attached (if applicable)
- [ ] Consent form template attached
- [ ] All required form fields completed
- [ ] Applicant identity verified

## Notifications Triggered (see also `4.3-esignature-notifications.md`)
- Submission received → Applicant + DPO Staff
- Returned for correction → Applicant
- Additional requirement requested → Applicant (item 7)
- Approved / Rejected → Applicant
- Clearance Issued (ready to download) → Applicant
