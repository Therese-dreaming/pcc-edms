# 1.2 — Module 1 (DPREQ): Workflow and Status States

> **2026-07-02:** Per `0.4-dpo-ethics-integration.md`, this is the **DPO track only** — one of
> two parallel tracks acting on the same Form 1 submission (the other being REMIS/Ethics, `3.3`).
> This module's `Approved` status is necessary but not sufficient for clearance issuance: the
> **Clearance Issued** step below now requires the Ethics track (`3.3`) to have also reached a
> positive decision. See `CHANGELOG.md`.

## Status Lifecycle (ASSUMPTION — propose for DPO validation)

```
Draft → Submitted → Screening → Under Review → Endorsed → Approved → Clearance Issued
                         |             |
                         v             v
                     Returned      Rejected
```

| Status | Description | Actor who moves it |
|---|---|---|
| Draft | Applicant is filling out form, not yet submitted | Applicant |
| Submitted | Application sent to DPO | Applicant |
| Screening | DPO checks completeness of documents | DPO Staff |
| Returned | Incomplete/incorrect — sent back to applicant with comments | DPO Staff |
| Under Review | Full substantive review of data privacy requirements | DPO Staff |
| Endorsed | DPO Staff recommends approval, forwards to Approver | DPO Staff → DPO Approver |
| Rejected | Application denied, with reason | DPO Staff / DPO Approver |
| Approved | DPO Approver signs off | DPO Approver |
| Clearance Issued | Certificate generated; **released to applicant only once the Ethics track (`3.3`) has also reached a positive decision and signed** — see `0.4-dpo-ethics-integration.md` | System (auto, on second signature) |

## Endorsement Procedure
1. DPO Staff completes screening checklist (see below).
2. If incomplete → status = Returned, with required comments field (mandatory).
3. If complete → status = Under Review.
4. DPO Staff completes substantive review, adds recommendation (Endorse / Reject).
5. If Endorse → routed to DPO Approver for final sign-off.
6. DPO Approver reviews and either Approves (triggers clearance generation + e-signature) or
   Rejects (with mandatory reason).

## Screening Checklist (ASSUMPTION — sample; confirm actual DPO checklist)
- [ ] Research proposal attached and legible
- [ ] Data privacy impact assessment attached (if applicable)
- [ ] Consent form template attached
- [ ] All required form fields completed
- [ ] Applicant identity verified

## Notifications Triggered (see also `4.3-esignature-notifications.md`)
- Submission received → Applicant + DPO Staff
- Returned for correction → Applicant
- Endorsed → DPO Approver
- Approved / Rejected → Applicant
- Clearance Issued (ready to download) → Applicant
