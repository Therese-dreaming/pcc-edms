# 5.1 — Reports: Shared (Both DPO and ORD)

## Report: Applications by Department
| Attribute | Detail |
|---|---|
| Owner | DPO and ORD (each sees their own module's data) |
| Data source | DPREQ + REMIS records |
| Grouping | Department/School |
| Metrics | Count of applications, breakdown by status |
| Filters | Date range, department, status |
| Output | Table + bar chart; export PDF/Excel |

## Report: Compliance Monitoring Report
| Attribute | Detail |
|---|---|
| Owner | DPO and ORD |
| Data source | DPREQ compliance declarations; REMIS monitoring records (`3.4`) |
| Metrics | Number compliant / minor issues / major issues / non-compliant |
| Filters | Date range, department, compliance status |
| Output | Table; export PDF/Excel |

> ASSUMPTION: DPO's version of this report tracks clearance conditions/compliance attestations,
> while ORD's version tracks study monitoring compliance status. Confirm whether these should be
> unified or kept as two separate report definitions sharing the same name.

## Report: Incident Summary (new, 2026-07-02)
| Attribute | Detail |
|---|---|
| Owner | ORD (REMIS incidents); DPO is CC'd/notified for Data Breach and Confidentiality Breach types, see `3.5-remis-incident-reporting.md` |
| Data source | REMIS incident records (`3.5`) |
| Metrics | Count by incident type, by severity, by status (Reported/Under Investigation/Corrective Action/Resolved/Closed); average time-to-resolution |
| Filters | Date range, department, incident type, severity |
| Output | Table + breakdown chart; export PDF/Excel |

> Added because `3.5-remis-incident-reporting.md` (new module, see `CHANGELOG.md`) had no
> corresponding report definition — incident data would otherwise be captured but never
> surfaced.
