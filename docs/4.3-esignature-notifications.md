# 4.3 — E-Signature and Notification Dashboards

## E-Signature Requirements
- Applies to: DPREQ clearances, DPNDA agreements, REMIS clearances
- Signature capture method (ASSUMPTION — choose one, confirm with legal/DPO):
  - Draw-on-screen signature pad, OR
  - Typed name + timestamp + IP/device log treated as legally binding e-signature, OR
  - Third-party e-signature provider integration
- Every signature event stores: signer name, role, timestamp, IP address, and the exact
  document version signed
- Signed documents are locked (read-only) after execution; further changes require a new
  version/amendment record

## Notification Dashboards (DPO and ORD)
Each office has a dashboard showing, at minimum:

| Widget | Data Source |
|---|---|
| New Submissions (unscreened) | DPREQ / REMIS / DPNDA records with status = Submitted |
| Pending My Action | Records assigned to the logged-in reviewer/approver |
| Returned/Revisions Requested (awaiting applicant) | Records with status = Returned/Revisions |
| Overdue Monitoring (ORD only) | REMIS records past Monitoring Due Date |
| Recently Completed | Records completed in last 7/30 days |

## Notification Channels
- In-app notification bell (required) — built.
- Email notification (required, mirrors in-app) — built (`docs/HANDOFF.md` Part E).
- SMS (optional) — decided against 2026-07-04: the project is meant to run entirely free apart
  from deployment hosting, and every real SMS gateway is a paid service. Not built by design.
