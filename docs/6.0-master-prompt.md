## Prompt

You are acting as a solutions architect and full-stack developer. I am providing the complete,
field-level specification for **PCC-EDMS** (PCC Electronic Document Management System) as a set
of numbered markdown files:

- **0.x — Foundations:** `0.1-purpose-and-scope.md`, `0.2-stakeholders-and-roles.md`,
  `0.3-glossary.md`
- **1.x — Module 1 (DPREQ):** `1.1-dpreq-application-form.md`, `1.2-dpreq-workflow.md`,
  `1.3-dpreq-documents.md`
- **2.x — Module 2 (DPNDA):** `2.1-dpnda-nda-template.md`, `2.2-dpnda-workflow.md`
- **3.x — Module 3 (REMIS):** `3.1-remis-application-form.md`, `3.2-remis-screening-risk.md`,
  `3.3-remis-review-workflow.md`, `3.4-remis-monitoring-archiving.md`
- **4.x — Core System Infrastructure:** `4.1-user-roles-permissions.md`,
  `4.2-file-management-naming.md`, `4.3-esignature-notifications.md`,
  `4.4-audit-trail-status-tracking.md`
- **5.x — Reports:** `5.1-reports-shared.md`, `5.2-reports-ord.md`, `5.3-reports-dpo.md`

Read all files as a single unified specification before responding.

**Important:** Many fields, workflow states, and thresholds in these files are marked
**ASSUMPTION** — they are my best proposal, not confirmed institutional policy. Treat them as a
draft baseline, not ground truth.

**Your task:**

1. Summarize your understanding of the three modules and how the 4.x infrastructure and 5.x
   reports connect to them, in your own words.
2. List every item marked ASSUMPTION or "open question" across all files, grouped by file, as a
   single consolidated question list for me to answer before you design the data model.
3. Once I've answered (or told you to proceed with the assumptions as-is), propose:
   a. A system architecture (frontend, backend, database, auth, file storage, e-signature)
   b. A normalized data model (entities, key fields, relationships) covering users, DPREQ
      applications, DPNDA/Placement records, REMIS applications, documents, workflow/status
      history, and audit log — sufficient to generate every report in `5.1`–`5.3` without manual
      data compilation
   c. API/module boundaries between DPREQ, DPNDA, and REMIS vs. shared services (auth, file
      storage, notifications, audit trail, reporting)
4. Ask me to confirm the architecture and data model before generating any code.
5. Once confirmed, implement module by module — DPREQ, then DPNDA, then REMIS, then the
   reporting module — in the stack I specify (ask me if I haven't specified one).

Do not skip step 2 or step 4. Surfacing gaps and getting my confirmation matters more than
speed, especially given DPO's ownership of sensitive personal data.
