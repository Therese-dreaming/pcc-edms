# 3.4 — Module 3 (REMIS): Monitoring and Completion

> **2026-07-02:** Split into Monitoring (FRS §XII) and Completion (FRS §XIV) as two distinct
> modules per the FRS — the previous version had a thin placeholder Monitoring section and no
> Completion Module at all; Archiving is now correctly modeled as the *outcome* of Completion,
> not a parallel process. See `CHANGELOG.md`.
>
> **2026-07-04:** Monitoring cadence confirmed with the requester — every month, since most
> studies here finish in 3-4 months anyway. No longer an open ASSUMPTION. See `docs/HANDOFF.md`
> Part G.

## Monitoring Module (FRS §XII)
For approved, in-progress studies, in status `Monitoring` (`3.3`):
- Periodic Research Progress Report submission by researcher, **every month** (FRS doesn't
  specify a cadence; confirmed with the requester 2026-07-04 — no longer an ASSUMPTION).
- Ethics Reviewer logs monitoring notes/compliance status
- Supporting documents may be attached to each progress report (FRS §XII, confirmed)

### Research Progress Report Fields (FRS §XII, confirmed)
| Field | Type |
|---|---|
| Status of Study | Dropdown/Text |
| Participants Recruited | Number |
| Ethics Concerns | Text area |
| Protocol Deviations | Text area |
| Corrective Actions | Text area |
| Supporting Documents | File(s) |

### Derived Fields (not explicit in FRS, computed rather than stored)
| Field | Type |
|---|---|
| Monitoring Due Date | Date — computed by `RemisMonitoringService::monitoringDueDate()` (last progress report, or monitoring start, + 1 month); not a stored column. Backs the ORD dashboard's Overdue Monitoring widget. |
| Progress Report Submitted? | Yes/No |
| Compliance Status | Dropdown (Compliant / Minor Issues / Major Issues / Non-Compliant) |

Non-compliance or protocol deviation flags feed the **Compliance Monitoring Report** (`5.1`). A
Data Breach, Confidentiality Breach, or other serious concern discovered during monitoring is
filed via the **Incident Reporting Module** (`3.5`), not recorded only as a free-text note here.

## Completion Module (FRS §XIV)
Triggered when the researcher submits a Final Ethics Completion Report, moving status from
`Monitoring` to `Closed` (`3.3`).

### Final Ethics Completion Report Fields (FRS §XIV, confirmed)
| Field | Type |
|---|---|
| Completion Date | Date |
| Final Participant Count | Number |
| Compliance Statement | Text area |
| Publication Status | Dropdown/Text |
| Data Storage Location | Text |
| Final Outputs Uploaded | File(s) |

### System Action (FRS §XIV, confirmed)
On acceptance of the Completion Report, the system:
1. Closes the case (status → `Closed`).
2. Archives the record (status → `Archived`).

## Archiving
| Field | Type |
|---|---|
| Archive Date | Date (auto) |
| Final Outcome | Dropdown (Completed / Discontinued / Withdrawn — Discontinued/Withdrawn kept
  in the enum for schema forward-compatibility only; the requester decided 2026-07-04 against
  building a separate discontinuation workflow, since a stalled study can just stay in
  `Monitoring` indefinitely) |
| Archived By | User reference (System, auto, on Completion acceptance) |

Archived studies remain searchable in the repository (read-only) and are the data source for
the **Archive Studies Report** (`5.2-reports-ord.md`) and **Annual Ethics Report** (`5.2`).
