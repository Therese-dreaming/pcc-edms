# 4.1 — User Creation, Validation, and Rights Management

## User Creation
| Field | Type | Required | Notes |
|---|---|---|---|
| Full Name | Text | Yes | |
| Email Address | Email | Yes | Used as login / unique identifier |
| Role | Dropdown | Yes | See role list in `0.2-stakeholders-and-roles.md` |
| Department/Office (if applicable) | Dropdown | Conditional | |
| Account Status | Dropdown | Yes | Pending Validation / Active / Suspended / Deactivated |

## Validation Flow (ASSUMPTION)
1. Self-registration (external users) or Admin-created (internal/staff) account
2. Email verification (confirmation link)
3. For staff/reviewer roles: Admin manually validates and assigns role before activation
4. Activated accounts can log in and access role-appropriate features

## User Classification and Modification of Rights
- Admin can reassign a user's role at any time (e.g., promote Reviewer to Approver)
- Role changes are logged in the audit trail (`4.4-audit-trail-status-tracking.md`)
- Bulk role import for OJT batches — confirmed required by the requester (2026-07-04) and built
  the same day (`docs/HANDOFF.md` Part H): a CSV upload with a validate-then-confirm preview
  step, extending the Part F Admin UI.

## Permission Enforcement
- All module actions (submit, screen, review, endorse, approve, sign, report) must check the
  acting user's role against the capability matrix in `0.2-stakeholders-and-roles.md`
- Unauthorized actions return a clear access-denied response and are logged as an audit event
