# 3.5 — Module 3 (REMIS): Incident Reporting Module

> **New file, added 2026-07-02.** This entire module existed in
> `REMIS_Functional_Requirements_Specification.md` (FRS §XIII) but had no corresponding file in
> the original `3.1`–`3.4` set — a data-breach/incident reporting pathway is a compliance
> requirement, not an optional feature, especially given DPO's stake in any data-related
> incident. See `CHANGELOG.md`.

## Purpose
Allows an incident occurring during an active or monitored study to be reported, tracked, and
resolved, independent of the study's normal status lifecycle (`3.3`).

## Who Can File (ASSUMPTION — FRS does not restrict the filer role; confirm with ORD)
- Researcher (PI or co-researcher on the study)
- Ethics Secretariat (on behalf of a participant complaint received directly)
- Ethics Reviewer / Ethics Committee Chair (on discovery during review or monitoring)

## Incident Types (FRS §XIII, confirmed)
- Participant Complaint
- Data Breach
- Confidentiality Breach
- Psychological Harm
- Protocol Violation
- Other Ethics Concern

## System Functions (FRS §XIII, confirmed)

### Immediate Notification
On filing, the system immediately notifies:
- Ethics Committee Chair
- Ethics Secretariat
- **If Incident Type = Data Breach or Confidentiality Breach:** DPO Staff (cross-module
  notification — ASSUMPTION, recommended: this is the primary integration point between REMIS
  and the DPO side of PCC-EDMS, since a REMIS-study data breach is also a DPO matter under the
  Data Privacy Act)

### Incident Tracking
| Field | Type |
|---|---|
| Incident Status | Dropdown (Reported / Under Investigation / Corrective Action in Progress / Resolved / Closed) |
| Assigned To | User reference |
| Investigation Notes | Text area, append-only |

## Relationship to Monitoring (`3.4`)
An incident may be filed independent of a scheduled progress report, or referenced from one
(e.g., a Research Progress Report's "Ethics Concerns" field may link to a filed incident rather
than duplicating the description). A study is **not required to be paused** on incident filing
by default — pausing is a Committee decision (ASSUMPTION — confirm whether certain incident
types, e.g. Data Breach, should auto-trigger a monitoring hold).

## Reporting

`5.1-reports-shared.md` should be extended to include incident counts/types by severity, not
