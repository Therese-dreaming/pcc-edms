# 2.2 — Module 2 (DPNDA): Workflow and Status States

> **2026-07-02:** Per `2.1`'s split, this status lifecycle describes the **OJT/Trainee NDA**
> (Form 5) flow specifically. The **Research Team NDA** (Form 2) is simpler — each team member
> signs (order not specified by the source form; ASSUMPTION: parallel, not sequential), and once
> **all** members have signed it is Completed and becomes a precondition for the DPO track
> (`1.2`) reaching `Approved` — it does not have a separate Coordinator-countersignature step
> since there is no coordinator role in the research-team case. See `CHANGELOG.md`.

## Status Lifecycle — OJT/Trainee NDA, Form 5 (ASSUMPTION)

```
Draft → Sent for Signing → Trainee Signed → Coordinator Countersigned → Completed/Archived
                                  |
                                  v
                              Declined
```

| Status | Description | Actor |
|---|---|---|
| Draft | Coordinator prepares NDA record for a trainee | Dept Coordinator |
| Sent for Signing | Trainee notified to review and sign | System → Trainee |
| Trainee Signed | Trainee has applied e-signature | Trainee |
| Declined | Trainee declines to sign (with reason) | Trainee |
| Coordinator Countersigned | Host department confirms/countersigns | Dept Coordinator |
| Completed/Archived | Fully executed NDA stored in repository | System (auto) |

## Notifications
- NDA ready for signing → Trainee
- Trainee signed → Dept Coordinator
- Fully executed → Trainee + Dept Coordinator + DPO (for records)
- Declined → Dept Coordinator + DPO

## Tracking Use
Every DPNDA record feeds directly into DPO reports on NDA completion, OJT counts, and
whereabouts (see `5.3-reports-dpo.md`) — placement dates and department/school fields on this
record are the primary source for those reports.
