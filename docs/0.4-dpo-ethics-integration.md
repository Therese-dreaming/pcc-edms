# 0.4 — DPO ↔ Ethics (REMIS) Integration Model

> **New file, added 2026-07-02.** Written after reconciling `reqs/DPO EFORM 1/2/3/5 SAMPLE.pdf`
> — four EVP-approved PCC forms not previously incorporated into this doc set — against
> `REMIS_Functional_Requirements_Specification.md`. The two sources initially looked
> contradictory (see `CHANGELOG.md` for the full reconciliation note); this file records the
> resolved model. **Confirmed with the requester** (not an ASSUMPTION): there are two
> departments, DPO and Ethics (REC/ORD). REMIS covers Ethics processes only — DPO is a separate,
> parallel track that this pass adds explicit integration points for.

## The resolved model

A research application has **one intake, two internal review tracks, one joint output**:

```
                         Form 1 (single application)
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                                 ▼
            DPO track (1.x)                   Ethics track (3.x / REMIS)
     DPO screening → review → approval    Endorsement chain → Ethics Secretariat
     (+ Form 2: Research Team NDA,        screening → risk classification →
       DPO-POL-005, if a team)            Ethics Reviewer review → Committee decision
                    │                                 │
                    └───────────────┬───────────────┘
                                    ▼
                    Form 3 — Joint Clearance Certificate
                    Co-signed: DPO Officer + Research Ethics Head
                    NOT released/downloadable until BOTH signatures exist
```

## Form-to-module mapping

| Form (source: `reqs/`) | Policy | What it is | Maps to |
|---|---|---|---|
| **Form 1** — Online Application for Data Privacy and Ethics Review | DPO-POL-005 | Single researcher-facing intake form. One submission, not two. | Entry point for **both** `1.x` (DPREQ/DPO track) and `3.x` (REMIS/Ethics track) — see `system-design.md`'s new `research_applications` table |
| **Form 2** — Non-Disclosure Agreement (research team) | DPO-POL-005 | NDA signed by the researcher/team lead and every co-researcher (Leader/Member roles) | New `research_team_ndas` entity — **distinct from Form 5**, see `2.1-dpnda-nda-template.md` |
| **Form 3** — Data Privacy and Research Ethics Clearance | DPO-POL-005 | The single, joint clearance certificate. Co-signed by the **DPO Officer** and the **Research Ethics Head**. Clearance is not accessible to the researcher unless both signatures are present. | `clearance_certificates`, now attached to `research_applications` (the shared parent), gated on dual sign-off — see `system-design.md` §3.1 |
| **Form 5** — Non-Disclosure Agreement for On-the-Job Trainee | DPO-POL-002 | NDA for OJT/trainee placements, signed by Trainee + Department Head. Replaces the old paper "NDA-4." | `dpnda_records` (unchanged in spirit from the original `2.1`/`2.2`, now scoped explicitly to OJT/trainee placements only, not research teams) |

## What this resolves

- **Why REMIS's elaborate endorsement chain (Adviser → Program Head → Dean), Ethics
  Secretariat/Reviewer/Chair split, and risk tiering don't appear anywhere on Form 1:** they
  aren't researcher-facing. Form 1 is the single front-door intake; the FRS-derived process in
  `3.2`/`3.3` is the Ethics side's **internal back-office handling** of that same submission.
  DPO's own screening/review (`1.2`) is the DPO side's internal back-office handling of the
  identical submission, running in parallel. Neither track is a separate application the
  researcher fills out twice.
- **Why Form 3 has two signature blocks:** because the two tracks above are independent approval
  chains that must **both** conclude before a clearance is valid. This is now a hard gate, not
  a documentation nuance — see the confirmation rule below.

## Confirmation rule (system-enforced, not just a form field)

The system must not make the clearance certificate PDF downloadable, nor mark
`clearance_certificates.status = issued`, until **both** `dpo_signed_by`/`dpo_signed_at` and
`ethics_signed_by`/`ethics_signed_at` are populated (`system-design.md` §3.1). A certificate
with only one signature exists as a record (so each office can see the other is still pending)
but is not released to the applicant. This directly implements the requester's instruction:
"Clearance should not be accessible by the researchers if only one signature is signed."

## Open questions this raises (add to `9.1`'s consolidated list)

- 🔴 **Does every Form-1 submission require the full REMIS track** (endorsement chain → Ethics
  Secretariat screening → risk classification → committee review), or only studies meeting some
  threshold (e.g., involving human subjects beyond a certain risk level)? Form 1's checklist
  (minors, harm/risk, confidentiality) reads as a screening trigger, not proof every study needs
  the full committee process — needs ORD/Ethics Secretariat confirmation. Until answered, this
  doc set assumes **every application goes through both tracks**.
- 🟢 **Role title reconciliation — confirmed 2026-07-04 by the requester:** "Research Ethics
  Head" (Form 3) and "Ethics Committee Chair" (FRS/`0.2`/`3.x`) are one person under two labels,
  not two distinct signatories. No code change needed — `joint-clearance.blade.php` already
  prints the applicant-facing "Research Ethics Head" label while the system internally tracks the
  signatory as the `ethics_committee_chair` role; this confirms that existing split is correct as-is.
- 🔴 **Form 2 applicability:** Form 1's checklist item 3 ("voluntary participation") and the NDA
  purpose statement suggest Form 2 (Research Team NDA) is required for *all* research
  applications with human respondents, not just some — confirm whether solo-researcher
  applications still require Form 2 (the form supports a 1-person "group").

## What did *not* change

- Form 5 (OJT NDA) and the `Placement` entity (`system-design.md` §3.3) are unaffected by this
  integration — OJT/trainee placements never touch the Ethics track, only DPO.
- Module ownership is unchanged: DPO still owns `1.x`/`2.x` data, Ethics/ORD still owns `3.x`
  data. What's new is the shared parent record and the joint-clearance gate, not a merge of the
  two departments' review authority.
