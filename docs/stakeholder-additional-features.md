# Research Ethics & Data Privacy Clearance System
## Consolidated Project Planning Notes

> This document consolidates proposed enhancements and implementation plans for the existing Research Ethics & Data Privacy Clearance System.

---

# DPO DEPARTMENT

## DPREQ (Data Privacy Requirements)

### 1. Independent Certificate Issuance
**Priority:** High

Certificates for **DPREQ** shall be generated independently and **must not be co-signed** with REMIS certificates.

#### Rationale

There are situations where:

- The applicant satisfies DPO requirements but not Ethics requirements.
- The applicant satisfies Ethics requirements but not DPO requirements.

Each department should therefore issue its own clearance independently.

---

### 2. Certificate Control Number
**Priority:** High

Every issued certificate shall contain a **unique Control Number**.

#### Requirements

- Auto-generated by the system
- Never reused
- Searchable
- Printed on the certificate
- Used for authenticity verification

#### Example

```
DPREQ-2026-000145
```

Benefits:

- Certificate authenticity
- Easier tracking
- Audit trail
- Identification of issued documents

---

### 3. Versioned File Submission
**Priority:** High

Applicants may re-submit documents during the review process.

#### Requirements

- Existing files must **never be overwritten**.
- Every upload becomes a new version.
- Reviewers should be able to compare:
  - Previous submission
  - Current submission
- Older versions remain available until final clearance is issued.
- After clearance issuance, previous versions may be archived or deleted according to the retention policy.

#### Suggested Structure

```
Application
├── Version 1
├── Version 2
├── Version 3
└── Final Approved
```

Benefits

- Complete audit trail
- Easier document comparison
- Prevents accidental data loss

---

### 4. Login Page Compliance Information
**Priority:** Medium

The login page should display compliance information before users sign in.

Display:

- Privacy Policy
- Terms and Conditions
- Data Privacy Notice
- Consent Statement

Suggested Layout

```
-----------------------------------------
| Login Form | Privacy & Terms          |
|            |                          |
| Username   | Privacy Policy           |
| Password   | Terms & Conditions       |
| Login      | Consent Notice           |
-----------------------------------------
```

Benefits

- Better transparency
- Immediate user awareness
- Compliance with data privacy requirements

---

### 5. Adviser-Managed Account Creation
**Priority:** High

To reduce fake accounts, duplicate registrations, and fraudulent submissions, applicants shall **not** create their own accounts.

Instead, advisers initiate account creation.

## Proposed Workflow

```
Adviser
    │
    │ Creates Applicant Account
    ▼
System
    │
    │ Generates activation email
    ▼
Applicant
    │
    │ Activates account
    │
    │ Creates password
    ▼
Applicant Dashboard
```

### Adviser Inputs

- Student Number
- Applicant Name
- Email Address
- Department
- Research Title (optional)

### System Responsibilities

Automatically:

- Generate account
- Generate activation link
- Send activation email
- Allow applicant to set password

Advantages

- Reduced adviser workload
- Prevent duplicate registrations
- Better applicant verification
- One verified account per applicant

---

### 6. Automatic File Naming Convention
**Priority:** High

All uploaded files shall be automatically renamed by the system to maintain consistency and simplify document management.

#### Naming Format

```
REC-{MODULE}-{DEPARTMENT}-{CONTROLNO}_{YYYYMMDD}_{FILELABEL}
```

#### Components

| Component | Description | Example |
|-----------|-------------|---------|
| REC | System prefix | REC |
| MODULE | Application module | NDA / REQ / REMIS |
| DEPARTMENT | Applicant department | JHS / SHS / COLLEGE |
| CONTROLNO | Unique application number | 0001 |
| YYYYMMDD | Upload date | 20260716 |
| FILELABEL | Standard document label | APPROVALLETTER |

#### Examples

```
REC-NDA-JHS-0001_20260716_APPROVALLETTER.pdf

REC-REQ-COLLEGE-0158_20260720_CONSENTLETTER.pdf

REC-REMIS-SHS-0235_20260722_RESEARCHPROPOSAL.pdf
```

#### Standard File Labels

- APPROVALLETTER
- CONSENTLETTER
- INFORMEDCONSENT
- ENDORSEMENTLETTER
- RESEARCHPROPOSAL
- QUESTIONNAIRE
- SURVEYFORM
- DATASET
- DATAPRIVACYFORM
- ETHICSFORM
- PERMISSIONLETTER
- ASSENTFORM
- OTHERDOCUMENT

#### Workflow

```
Applicant uploads document
        │
        ▼
System identifies:

• Module
• Department
• Control Number
• Upload Date
• Document Type

        │
        ▼
Generate standardized filename
        │
        ▼
Store file
```

#### Version Example

```
REC-REQ-COLLEGE-0235_20260722_APPROVALLETTER_V1.pdf

REC-REQ-COLLEGE-0235_20260724_APPROVALLETTER_V2.pdf
```

The original filename may be retained in the database for reference but shall not be used as the stored filename.

# DPNDA (Data Privacy Non-Disclosure Agreement)

## 1. Enhanced Electronic Signature Identification
**Priority:** High

Every electronic signature shall include signer identification information.

Each signature should record:

- Name of Signatory
- Date Signed
- Time Signed
- IP Address (optional)
- Device Information (optional)

Example

```
Electronically signed by

Juan Dela Cruz

July 22, 2026
8:43 PM
```

Purpose

- Stronger legal evidence
- Better audit trail
- Improved verification

# ETHICS DEPARTMENT

## REMIS

### 1. Independent Certificate Issuance
**Priority:** High

REMIS certificates shall be issued independently from DPREQ certificates.

Ethics approval must not depend on DPO approval, and vice versa.

---

### 2. Certificate Control Number
**Priority:** High

Every REMIS certificate shall contain a unique Control Number.

Example

```
REMIS-2026-000098
```

---

### 3. Individual Member Electronic Signature Workflow
**Priority:** High

Research applications often require signatures from multiple researchers.

Instead of one shared signing page, the system shall generate a **unique signing link for every research member**.

---

### Required Research Member Information

Each application shall collect:

- Member Name
- Email Address
- Role (optional)

Example

```
Research Members

• Juan Dela Cruz
• Maria Santos
• Pedro Reyes
```

---

### Signing Workflow

```
Research Application
        │
        ▼
Generate Unique Signing Links
        │
        ├── Juan
        ├── Maria
        └── Pedro
                │
                ▼
Each member signs independently
                │
                ▼
System records:

• Signer Identity
• Signature
• Timestamp
• Completion Status
```

Each signing link shall:

- Be unique
- Be associated with one member only
- Expire after a configurable period
- Be usable only once
- Be delivered through email

Benefits

- Better accountability
- Improved legal defensibility
- Easier monitoring of pending signatures
- Prevent unauthorized signing
